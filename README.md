# AirNoti

Небольшой неофициальный Android-мост: выбранные уведомления телефона → короткий тактильный сигнал Google Fitbit Air. Kotlin, Compose Material 3, один экран. Не связан с Google или Fitbit.

**Alpha: экспериментальный частный протокол.** Подтверждение CoAP и чтение настройки не доказывают, что человек почувствовал вибрацию. Результаты испытаний находятся в [VALIDATION.md](docs/VALIDATION.md); не считайте тесты upstream проверкой AirNoti.

## Установка и включение

1. Скачайте APK и SHA-256 из Releases, сравните хеш. Разрешите установку этому источнику в системных настройках.
2. Сначала сопрягите Fitbit Air с Google Health на этом же телефоне. Не удаляйте сопряжение и не сбрасывайте браслет.
3. Откройте AirNoti, разрешите Bluetooth и доступ к уведомлениям. Если Android показывает ограниченные настройки, используйте документированный системный пункт в сведениях о приложении, если доступен. Отключать Play Protect не требуется.
4. Выберите свой Air из сопряжённых устройств. Другие устройства показаны, чтобы переименование Air не мешало выбору; поддержка других моделей не заявляется.
5. Отметьте приложения или «Получать от всех приложений», включите переключатель, нажмите «Проверить вибрацию».
6. Проверьте физический сигнал и затем синхронизацию Google Health. При неопределённом результате проверьте силу вибрации в Google Health перед следующим тестом.

Первый запуск: пересылка выключена. В режиме «все» индивидуальный выбор сохраняется, галочки недоступны; новые приложения с обычным запуском включаются автоматически. Служебные пакеты без запуска исключены и в этом режиме. Пустой индивидуальный выбор не пересылает ничего. Тестовая кнопка тоже требует включённого переключателя.

«По умолчанию» читает текущую силу и отправляет одно сообщение с переходом на другую силу и обратно. «Слабая»/«Сильная» явно изменяют общую настройку браслета при следующем сигнале. Произвольное управление мотором не заявляется. Будильники не читаются и не изменяются.

## Совместимость

- APK: Android 11/API 30+, BLE, уже сопряжённый Air; библиотеки `arm64-v8a`, `armeabi-v7a`, `x86_64`. 32-bit x86 не поддерживается.
- **Текущая Google Health требует Android 14+**, согласно [официальной справке](https://support.google.com/product-documentation/answer/14226283), проверенной 2026-11-15. Возможность установить APK на Android 11–13 не означает поддержку актуальной Google Health на этих ОС.
- Нет специфичных для Pixel API. Samsung, Xiaomi, OnePlus и другие производители — кандидаты на совместимость при выполнении требований, не проверенные модели.
- Протокол upstream сообщает о тесте Air firmware `67.20001.253.2`, Pixel 7 Pro. Это **не** результат испытания AirNoti. Новая прошивка может изменить протокол.
- Android APK не работает на iPhone. iOS-реализация в проект не входит.

## Поведение и ограничения

Уведомления принимает системный `NotificationListenerService`. Собственные, ongoing/foreground-service, progress и media/service уведомления исключаются. При подключении listener активные уведомления только запоминаются, не проигрываются. Для MessagingStyle учитываются текст, время сообщения и отправитель исключительно в памяти: новый элемент под прежним ID не теряется. Для других уведомлений одинаковое содержимое с прежним ID подавляется — если приложение не сообщает различимые данные, одинаковые новые события могут быть неотличимы.

Объединение — 700 мс, минимум 3 с между началами отправок, очередь максимум 16 событий, срок годности 10 с до начала отправки. Групповая сводка подавляется, если обработан дочерний элемент. Доставка не гарантируется: потерянные и устаревшие события не накапливаются на диске.

Соединение открывается только по событию или тестовой кнопке: GATT → Gattlink → DTLS BOOTSTRAP → CoAP `/settings` → проверка → ограниченная передача канала Google Health → закрытие. Нет автоматического повтора команды с неопределённым результатом. Готовность не означает постоянно открытое соединение.

Нет сканирования, heartbeat, WorkManager, медицинских чтений, wake lock, сервера и аккаунта. Короткая операция живёт в процессе системно подключённого listener; обычный Service и попытки обойти ограничения запуска FGS не используются. ОС может оборвать операцию при завершении процесса. Глубокий простой и особенности OEM требуют измерения. Force stop не восстанавливается автоматически: снова откройте приложение. После обычного перезапуска listener восстанавливается ОС в пределах её политики, старые события не воспроизводятся.

При длительной занятости синхронизацией событие пропускается. Отзыв Bluetooth-доступа, выключение Bluetooth, выключение функции и уничтожение listener прекращают текущую операцию. Смена сохранённого адреса отменяет предыдущую. Если адрес перестал соответствовать сопряжённому устройству, выберите Air заново. CompanionDeviceManager оценён, но не добавлен: существующее сопряжение и адреса пока не проверены с CDM, постоянное наблюдение присутствия не нужно для этой версии.

Измеренного расхода батареи пока нет. Короткие соединения выбраны как ограниченный исходный вариант, а не как доказанно самый экономичный. Повторные handshake могут стоить дороже тёплого соединения при частых событиях. [Методика сравнения](docs/VALIDATION.md).

## Разрешения и приватность

Bluetooth Connect (Android 12+), legacy Bluetooth (Android 11), системный доступ к уведомлениям, Видимость ограничена приложениями с обычным значком запуска через декларацию queries. Служебные компоненты без запуска не показываются в выборе; предустановленные пользовательские приложения остаются. QUERY_ALL_PACKAGES не нужен.

Нет INTERNET, READ_SMS, контактов, Accessibility, root, разрешений на медицинские данные, местоположение и сканирование. Содержимое уведомлений не сохраняется и не логируется. DataStore хранит переключатели, имена пакетов, выбранный Bluetooth-адрес и режим силы; резервное копирование Android выключено. [Политика приватности](PRIVACY.md).

## Сборка

Нужны JDK 21 (CI и локальная проверка), Android SDK 37.0, Build Tools 36.0.0 и принятые лицензии SDK. Gradle 9.5.0 / AGP 9.3.3, версии зависимостей фиксированы. Создайте локальный `local.properties` с `sdk.dir` или задайте `ANDROID_HOME`.

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew :app:connectedDebugAndroidTest
```

В Windows используйте `gradlew.bat`. Подключённый телефон нужен только для `connectedDebugAndroidTest`; эти проверки не требуют Air и не подтверждают вибрацию. APK: `app/build/outputs/apk/debug/app-debug.apk`.

Транспорт встроен в единственный Android-модуль. Kotlin JNI bindings в `app/src/main/vendor` и `.so` в `app/src/main/jniLibs` сохранены отдельно от собственного кода. [Источники и лицензии](NOTICE), [исследование](docs/TRANSPORT.md). Нативную часть можно пересобрать на Linux с Python 3, Git, CMake, Ninja и NDK 28.2.13676358: `python3 tools/native/build.py --ndk "$ANDROID_HOME/ndk/28.2.13676358" --check`. Локально проверены хеши поставленных бинарников; полная пересборка native не подразумевается.

## Следующая версия и подпись

Для первого собственного ключа в PowerShell: `./tools/Initialize-Signing.ps1` (JAVA_HOME указывает на JDK). Скрипт отказывается перезаписывать существующий ключ. Ключ `.private/airnoti-release.p12` и пароли `.private/signing.properties` остаются локально, вне Git и релиза. Сохраните **оба файла** в защищённой резервной копии. Потеря ключа не позволяет обновить установленный APK с той же подписью.

Для следующего выпуска сохраните `applicationId = ru.itoltec.airnoti`, увеличьте `versionCode` и `versionName`, восстановите тот же ключ, запустите тесты и `./gradlew :app:assembleRelease`. Без локального signing.properties release собирается неподписанным; CI не имеет ключа. Debug локально использует тот же ключ только при его наличии, чтобы перейти на release без удаления настроек.
